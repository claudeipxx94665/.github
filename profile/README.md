<p>共享带宽到底会不会拖慢速度，这个问题吵了很多年，双方都能拿出例子。与其继续争，不如做一次能复现的对照：一条共享池线路、一条独享线路，同一台机器、同一个脚本、同一批目标地址，按四个时段各跑三轮，只记原始读数。下面把实验设置、白天读数、晚高峰读数和并发压测结果依次摆出来，最后说明这些数字在什么条件下才成立。</p>

<h2>一、实验怎么搭：一条共享、一条独享，脚本不变</h2>
<p>对照实验最容易失败的地方是变量太多。这次只允许线路类型变化，其余条件在四十八小时内保持不动。</p>
<h3>固定住的五个条件</h3>
<p>同一台云主机（同可用区、同规格）；同一个 Python 脚本、同一份依赖锁文件；同一批 200 个目标地址，顺序固定；每轮跑 100 次请求，串行，超时 30 秒；记录字段固定为时间戳、状态码、首字节耗时、总耗时、是否重试。共享线路取自某服务商的共享池，标称 100Mbps；独享线路为静态住宅地址，标称 50Mbps。价格大致落在每月 30 至 80 元与 80 至 300 元两个区间，仅供参考。</p>
<h3>四个时段怎么选</h3>
<p>10:00 代表工作日上午，15:00 代表下午平稳段，21:00 代表晚高峰峰值，23:30 代表高峰回落。每个时段跑三轮，取中位数，避免单次抖动影响判断。三轮之间间隔十分钟，让连接池自然冷却。</p>
<h3>测量工具和命令</h3>
<p>网络层用 <code>mtr -rwzc 100 目标域名</code> 看往返时延与丢包，用 <code>curl -o /dev/null -s -w "%{http_code} %{time_starttransfer} %{time_total}\n"</code> 记首字节和总耗时，应用层用脚本自己统计状态码分布。三类数据分开存，避免把网络问题和应用问题混在一列。</p>

<h2>二、白天两组读数几乎重合</h2>
<p>上午和下午的结论让人有点失望：两条线路的差距在误差范围内，看不出谁更好。</p>
<h3>延迟和抖动</h3>
<p>10:00 时段，共享线路的往返中位数 142ms、抖动标准差 18ms，独享线路 138ms、17ms。15:00 时段分别是 136ms 和 133ms。差距都在 5ms 以内，低于当天的自然波动。这说明在池子空闲时，共享带宽并不会明显拖慢单条连接，标称值的差异也被实际链路掩盖了。</p>
<h3>成功率</h3>
<p>两个时段的成功率都是 99% 上下，失败集中在超时的两三次，重试后基本恢复。首字节耗时的分布也接近，P50 在 300ms 左右，P95 在 800ms 左右。如果只看白天的数据，结论会是"共享够用，不必多花钱"。</p>

<h2>三、晚八点之后，差距开始显形</h2>
<p>21:00 这一轮，两条线路的曲线明显分开了。不是独享变快了，是共享变慢了。</p>
<h3>P95 比中位数更能说明问题</h3>
<p>共享线路 21:00 的中位数 168ms，看着还行，但 P95 冲到了 720ms，P99 超过 1.8 秒，抖动标准差升到 96ms。独享线路同一时段中位数 145ms，P95 是 320ms，标准差 24ms。中位数差距只有 23ms，P95 差了 400ms，这就是"感觉卡"和"测速正常"能同时出现的原因。</p>
<h3>重试率翻了三倍</h3>
<p>共享线路的重试率从白天的 1.2% 升到 3.8%，独享线路从 0.7% 升到 1.1%。重试会进一步占用带宽，形成小范围的自我放大。23:30 高峰回落后，共享线路的 P95 回落到 380ms，说明这确实与时段负载相关，而不是线路本身劣化。</p>

<h2>四、把并发拉满，瓶颈出现在第三段</h2>
<p>单连接测不出带宽共享的真实影响，于是加了一组并发压测：同一脚本开到 20 并发，持续五分钟，看吞吐和失败率。</p>
<h3>吞吐天花板</h3>
<p>共享线路在 20 并发下总吞吐稳定在 18 至 25Mbps，继续加并发不再上升，说明被池子的分配策略限住了。独享线路在同样并发下达到 42Mbps 左右，接近标称值。这里要注意，共享池的标称 100Mbps 是池子上限，不是单账号可用值，销售话术里经常不区分。</p>
<h3>三段瓶颈的先后顺序</h3>
<p>压测时用 <code>mtr</code> 分段看，瓶颈依次出现在：出口网关（延迟抬升）、跨境链路（丢包 1% 到 3%）、目标站入口（429 增多）。共享与独享在前两段的差异最大，第三段基本一致。也就是说，带宽共享影响的是"路"，不影响"门"。门那边的限流，换多贵的线路都绕不开。</p>

<h2>五、这些结论在什么条件下成立</h2>
<h3>成立的范围</h3>
<p>结论对"跨境、晚高峰、单账号高并发"这三个条件同时成立的场景最有效。如果你的使用集中在白天、并发不超过 3，共享线路的性价比确实更高，多花的钱买不到体感差异。反过来，任务集中在 20:00 到 23:00，或者需要稳定的 P95，独享更划算。</p>
<h3>不成立的范围</h3>
<p>不同服务商的池子策略差别很大，有的按账号均分，有的按连接抢占，本文只测了两家。另外目标站自身的限流会掩盖线路差异，如果目标站在高峰期对同一出口统一限速，那线路再好也没用。复现时至少要跑满一个完整晚高峰，单次十分钟的测试不足以下结论。</p>

<h2>常见问答</h2>
<h3>共享带宽是不是一定比独享慢？</h3>
<p>答：空闲时段不一定，差异在误差范围内；高峰时段和并发上来之后差异明显。关键看你的使用时段和并发，不看标称带宽。</p>
<h3>标称 100Mbps 为什么实测只有 20Mbps？</h3>
<p>答：共享池的标称值是池子上限，不是单账号保证。单账号能拿多少取决于同时在线人数和分配策略。买之前问清楚"单账号保证带宽"这个数。</p>
<h3>晚高峰慢，换个地区能解决吗？</h3>
<p>答：有时可以。不同地区的池子负载不一样，但更根本的办法是换独享或者错峰。换地区只能碰运气，不是稳定方案。</p>
<h3>怎么判断是带宽问题还是目标站限流？</h3>
<p>答：看错误类型。带宽问题表现为超时、连接重置、吞吐上不去；限流表现为 429、403 或返回特定提示页。用同一个地址访问别的站点做对照，能快速区分。</p>

<h2>合规提示</h2>
<p>压测与对照实验应限于自有线路和自有目标，不得对第三方站点发起压力测试。测试流量应控制在合理范围，避免影响目标服务的正常运行。</p>
<p>线路选型应基于自身业务的真实需求，遵守服务商条款与所在地法律。共享资源的使用不应影响其他用户，恶意抢占带宽可能被服务商限制。</p>
<p>文中读数为特定环境下的单次实验结果，仅供参考，不同时间、不同地区、不同服务商会得到不同数值。</p>
